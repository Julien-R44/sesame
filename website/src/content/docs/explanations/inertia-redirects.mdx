## OAuth uses browser navigation

The authorize and consent controllers return HTTP redirects. Successful consent redirects to the client's registered callback, which can belong to another origin. These redirects are part of the OAuth browser flow.

An Inertia visit uses a request managed by the Inertia client. An external OAuth callback is a document navigation. The two need different handling in the application that owns the pages.

## The Sésame boundary

Sésame does not call an Inertia adapter or emit an Inertia external-location response. Its controllers use AdonisJS `response.redirect().toPath()`.

A consent page can use Inertia for its rendering while submitting the decision through a native HTML form. The form posts `auth_token` and `accept` to `/oauth/consent`, then the browser follows Sésame's redirect. The [login and consent guide](/guides/login-and-consent/) uses the same submission contract.

If your application sends consent through an Inertia request, your integration must convert the resulting external redirect to the external-location behavior supported by your Inertia adapter. That conversion belongs to your application's middleware or endpoint integration. Sésame has no built-in option for it.

The login page has the same boundary. After a session login, the browser returns to `/oauth/authorize` with the original authorization parameters. Preserving those parameters and choosing full-page navigation belong to your login implementation.
